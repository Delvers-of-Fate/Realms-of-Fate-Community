Modding / Achievements

Legacy engine achievements

Archived engine-fork documentation. These achievements, fields and triggers have not been ported to the current Delver mod prototype. Do not use these examples as current mod setup instructions. Open the current mod guide.

Achievements are defined in JSON and advanced by game events or editor triggers. The examples below cover discovery, combat, and scripted unlocks.

File setup

Create data/achievements.dat inside an enabled mod. This guide uses the engine’s default achievement filename. Definitions load through the normal mod stack; later definitions with the same ID replace earlier ones.

YourMod/
├── data/
│   └── achievements.dat
└── ui/
    └── achievements/
        └── crypt_warden.png

Each block below is a complete file you can use as a starting point. To combine examples, copy the object inside achievements into your existing array, separating objects with commas. Use unique IDs unless you intend to replace an achievement.

Values to change: change the achievement’s id, name, description and category. When changing a named target, update the matching editor eventTarget or monster achievementTarget too. Keep the event name shown in the example unless you want a different action to advance it.

In DelvEdit, place achievement triggers through Logic → Triggers → Achievement. The JSON defines the reward; the trigger or monster reports what happened.

Discover an area

Report a named event when the player crosses an entrance.

data/achievements.dat · complete file
Download 
{
  "achievements": [
    {
      "id": "discover_forgotten_crypt",
      "name": "Below the Forgotten",
      "description": "Discover the Forgotten Crypt.",
      "category": "Exploration",
      "event": "EVENT_COMPLETE",
      "target": "forgotten_crypt_discovered",
      "required": 1,
      "iconAtlas": "item",
      "iconTex": 89
    }
  ]
}

Editor setup

Property Value
triggerType PLAYER_TOUCHED
triggerResets false
reportEvent true
eventType EVENT_COMPLETE
eventTarget forgotten_crypt_discovered
amount 1
isSecret false

Place an Achievement trigger across the entrance and resize its collision bounds to cover the player’s path. Leave achievementId blank in event mode. Returning on another run can report the event again; required: 1 makes this a one-time unlock.

Discover a secret

Use the secret event already emitted by a regular trigger.

data/achievements.dat · complete file
Download 
{
  "achievements": [
    {
      "id": "find_a_secret",
      "name": "Behind the Walls",
      "description": "Discover a secret.",
      "category": "Exploration",
      "event": "DISCOVER_SECRET",
      "target": "*",
      "required": 1,
      "iconAtlas": "item",
      "iconTex": 89
    }
  ]
}

Editor setup

Property Value
triggerType PLAYER_TOUCHED
triggerResets false
isSecret true

Use a regular Trigger for the secret area. It reports DISCOVER_SECRET automatically when fired. The wildcard target accepts any secret. Do not also report the same event through an Achievement trigger: that would count it twice. For a specific secret, the event target is the trigger’s runtime entity ID; generated level chunks may prefix entity IDs. A named EVENT_COMPLETE event is easier to keep stable for a specific location.

Defeat a boss

Let the monster report its death to the achievement system.

data/achievements.dat · complete file
Download 
{
  "achievements": [
    {
      "id": "defeat_crypt_warden",
      "name": "The Warden Falls",
      "description": "Defeat the Crypt Warden.",
      "category": "Combat",
      "event": "KILL_BOSS",
      "target": "crypt_warden",
      "required": 1,
      "iconAtlas": "item",
      "iconTex": 89
    }
  ]
}

Editor setup

Property Value
isBoss true
achievementTarget crypt_warden

Set these fields in the monster’s Achievements group. No separate Achievement trigger is needed. KILL_BOSS is reported only when the final damage is attributed to the player. Set an explicit achievementTarget so renaming the monster does not change which achievement it advances.

Discover two different areas

Give each location its own permanent requirement ID.

data/achievements.dat · complete file
Download 
{
  "achievements": [
    {
      "id": "explore_ancient_depths",
      "name": "Into the Depths",
      "description": "Discover the crypt and the sunken library.",
      "category": "Exploration",
      "iconAtlas": "item",
      "iconTex": 89,
      "requirements": [
        {
          "id": "crypt",
          "label": "Discover the crypt",
          "event": "EVENT_COMPLETE",
          "target": "forgotten_crypt_discovered",
          "required": 1
        },
        {
          "id": "library",
          "label": "Discover the library",
          "event": "EVENT_COMPLETE",
          "target": "sunken_library_discovered",
          "required": 1
        }
      ]
    }
  ]
}

Editor setup

Property Value
reportEvent true
eventType EVENT_COMPLETE
eventTarget One location target per trigger
triggerType PLAYER_TOUCHED
triggerResets false

Place one Achievement trigger at each location. Use forgotten_crypt_discovered on the first and sunken_library_discovered on the second. Separate requirements ensure visiting the same location twice cannot complete both. When requirements is present, it replaces the top-level event, target and required fields.

Unlock from a scripted event

Address a single achievement directly from level logic.

data/achievements.dat · complete file
Download 
{
  "achievements": [
    {
      "id": "complete_warden_encounter",
      "name": "Silence in the Crypt",
      "description": "Complete the Warden encounter.",
      "category": "Combat",
      "event": "MANUAL",
      "target": "*",
      "required": 1,
      "iconAtlas": "item",
      "iconTex": 89
    }
  ]
}

Editor setup

Property Value
id warden_achievement_trigger
triggerType USE
triggerResets false
reportEvent false
achievementId complete_warden_encounter
unlockImmediately true

Place this Achievement trigger out of player reach. On the boss, set triggersOnDeath to warden_achievement_trigger. This awards encounter completion regardless of who dealt the final damage. Keep any existing death-trigger wiring: if the boss already targets other level logic, connect the achievement through that chain rather than overwriting it. The trigger’s entity id is the wiring address; achievementId selects the JSON achievement.

Use a custom icon

Show your artwork in the browser and the unlock popup.

data/achievements.dat · complete file
Download 
{
  "achievements": [
    {
      "id": "defeat_crypt_warden",
      "name": "The Warden Falls",
      "description": "Defeat the Crypt Warden.",
      "category": "Combat",
      "event": "KILL_BOSS",
      "target": "crypt_warden",
      "required": 1,
      "iconAtlas": "item",
      "iconTex": 89,
      "iconPath": "ui/achievements/crypt_warden.png"
    }
  ]
}

Save a square transparent PNG at YourMod/ui/achievements/crypt_warden.png. A simple 32 × 32 icon fits the game’s pixel art. Supply your own PNG; it is not included in this example. iconPath takes priority over iconAtlas and iconTex. Use forward slashes and a path relative to the mod root. A missing file currently produces a cyan error texture, so check the path if that appears. This example replaces the boss example with the same achievement ID; do not add both entries.

Field reference

Field Default Purpose
id Required stable ID Keep this unchanged after release. Achievement IDs are matched without case sensitivity.
name / description Achievement / empty Visible title and explanation.
category General Groups achievements in the browser.
hidden false Conceals the name, icon and details until unlocked.
event MANUAL Event enum, such as EVENT_COMPLETE, DISCOVER_SECRET or KILL_BOSS. Use the exact uppercase spelling.
target * Event target. Empty or * matches any target; named targets match without case sensitivity.
required 1 Positive progress needed to unlock.
requirements null Optional array of individual goals. Each has id, label, event, target and required. All must complete.
iconAtlas / iconTex item / 89 Registered atlas name and sprite index.
iconPath null Standalone image path relative to the mod root. Overrides atlas artwork.
Keep requirement IDs permanent. They are case-sensitive save keys. Older requirements without IDs use their array positions: keep their order unchanged. Adding IDs to shipped anonymous requirements needs a save migration. Duplicate requirement keys are rejected during loading.

Test before sharing

  1. Enable your mod and restart or reload the game so its definitions load.
  2. Use DelvEdit play testing to fire the trigger or defeat the boss. Preview achievements use temporary progress and do not change your real profile.
  3. Check the unlock popup and the achievement browser. Hidden achievements reveal their artwork and details only after unlocking.
  4. For multi-step goals, complete one requirement at a time and verify each advances independently.

If nothing unlocks

  • Check event names, target values and the JSON file’s achievements array.
  • With reportEvent = true, the trigger uses eventType and eventTarget; achievementId and unlockImmediately are ignored.
  • With reportEvent = false, use achievementId. Leave the legacy achievementName field empty.
  • Direct progress advances only the first MANUAL requirement in a multi-step achievement. Prefer event mode for multiple goals.
  • A trigger with triggerResets = false fires once for that instance, not once for the entire profile. Repeated runs can increase counters.
  • Already unlocked achievements do not unlock again in the normal profile. Use editor preview for repeated testing.
