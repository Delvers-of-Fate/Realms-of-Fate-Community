Install, update and restore

Before installing

Close Delver and DelvEdit. Back up your mod folder, game JAR and campaign saves. Use the mod ZIP and compatible manual-patch ZIP supplied with the prototype. This site does not yet publish those binary packages; it provides documentation and JSON examples.

1. Install the mod

Place the mod contents in mods/RealmsOfFate/ inside the Delver installation. Avoid an extra nested folder: mods/RealmsOfFate/modInfo.json must exist.

mods/RealmsOfFate/
  modInfo.json
  java/com/realmsoffate/…        compiled Java 8 classes
  source/com/realmsoffate/…      matching editable Java source
  editor-source/               editor companion source
  data/rof-classes.json
  data/currencies.json
  data/spells/*.json
  data/editor-theme.json
  data/rof-startup.json
  ui/spells/*.png

2. Enable the loader once

The inspected game's normal launcher ignores the mod-classes argument. Its loader still exists internally. The manual patch supplies one original launcher class and a replacement manifest that activates that loader and then calls Delver's original entry point.

  1. Copy the untouched delver.jar somewhere safe outside the game folder.
  2. Open delver.jar with a ZIP/JAR archive editor.
  3. Merge both folders inside jar-patch/ into the archive root. Keep existing com/ contents and replace the supplied manifest.
  4. Confirm com/realmsoffate/launcher/ModClassesLauncher.class and META-INF/MANIFEST.MF exist at those exact archive paths. Do not add the enclosing jar-patch folder.
  5. Save the archive and launch the regular Delver entry in Steam.

Do not patch DelvEdit.jar. The editor uses its separate --enable-mod-classes=true launch argument. No compiler is needed to play; source files accompany the compiled classes for editing and rebuilding.

Exact supported original JAR

A2D58E87B09F588FF8389508E43ACCF7D3C6CE949B5AA4D31D6380574EC095AE

This is the SHA-256 before patching, not after. Do not apply this archive patch to an unverified version. Java bytecode portability does not establish Mac/Linux launcher compatibility.

Updates and undo

For mod updates, preserve edited JSON, icons and metadata. Back up before merging new classes and their matching sources. Ordinary mod updates do not require repatching the game JAR. Steam updates or file verification can undo the loader patch; check the new game version before reapplying.

To undo the patch, close the game and restore the original JAR. Disable Java-dependent mods before returning to stock play. Restoring the JAR does not revert campaign changes; use your save backup if needed. Restoring a mod-only change means restoring its backed-up folder.

Troubleshooting

  • ClassTome class not found: check loader activation and the mod's java/ folder.
  • R does nothing: hold a custom ManaWand with multiple spells, close menus and stop charging an attack. Stock wands are unchanged. R now works in debug mode, but remove debug=true for normal play to avoid stock debug mouse controls.
  • Startup reports a failure: fix the named configuration and restart. “Continue anyway” does not repair the affected feature.
  • Editor looks unchanged: check its own launch arguments and restart DelvEdit.

Source and rebuild

The mod ZIP includes source/ and editor-source/. The patch ZIP includes source/ModClassesLauncher.java. Keep source matched to every release. In the developer workspace, workshop/RealmsOfFateClasses/SOURCE-AND-BUILD.md documents the build and test scripts. The patch build needs the supported unpatched JAR and a JDK; it tests an isolated copy, not the live installation.
